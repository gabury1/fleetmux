fleetmux

A tmux cockpit for running a fleet of AI coding agents.

One bash file. No runtime to install.

GitHub Latest release

The problem

Run five agents at once and the expensive one is not the slow session — it is the one that finished asking you a question forty minutes ago and has been idle ever since.

You cannot see that from outside the session, so you go in and look. Five times. Then you do it again in ten minutes.

What you get

⏸ waiting on you

The one that matters. It is named in the status bar, so you know which session is blocked without opening anything.

✻ working

Actually running right now — judged from agent hooks and CPU, not from guessing at what the screen looks like.

✓ finished while away

Unread results sit at the top of the list and clear themselves the moment you visit.

survives a reboot

fmux --restore brings the whole fleet back — every session in its own directory, each agent resuming its own conversation.

Why not just read the screen?

Because that was the first version, and it was wrong three separate ways. Spinner wording changes between releases. An idle session still repaints its status line. Attaching to a session reflows it and every heuristic shifts underneath you.

The screen is a rendering, not the content.

So state comes from the agent itself. Claude Code and Codex hooks report working / idle / waiting as they happen, and fmux draws what they said. The hooks are injected through a PATH shim that only fires inside tmux — your global config is never touched, and deleting one file removes every trace.

Install

curl -fsSL https://raw.githubusercontent.com/gabury1/fleetmux/main/install.sh | bash

Or read it first, which is the reasonable thing to do with any curl | sh — the README shows that path too. The installer checks its dependencies, never edits your crontab, and never takes a key or a file that is already someone else's. Requires tmux ≥ 3.2, fzf ≥ 0.64, bash. Linux and macOS; Windows via WSL2.
