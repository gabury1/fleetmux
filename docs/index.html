fleetmux

Keep the agent screen you already use. fmux adds one status line and one keystroke — nothing else to look at.

쓰던 에이전트 화면은 그대로 두고, 상태줄 한 줄과 단축키 하나만 더합니다.

One bash file. No dashboard, no app, no runtime.

bash 파일 하나예요. 대시보드도, 앱도, 런타임도 없습니다.

GitHub Latest release최신 릴리스

The problem문제

Running several agents usually means splitting the screen. Four agents, four panes.

에이전트를 여러 개 돌릴 때는 보통 창을 나눠서 띄워놓게 되죠. 넷을 띄우면 화면도 넷으로 쪼개집니다.

And then your eyes never settle. You keep choosing where to look, and the text keeps getting smaller. After an hour or two it is your eyes that give out first — not the machine, and not the agents.

그런데 그렇게 해놓으면 시선이 한 곳에 머물지를 못해요. 어디를 볼지 계속 고르게 되고, 글씨는 필연적으로 작아지고요. 한두 시간 지나면 기계도 에이전트도 아니고 눈이 먼저 지칩니다.

But there is only one reason to split the screen at all: you want to know which session needs you.
fmux starts there. Keep one session full size, and let a single line at the bottom speak for the rest.

그런데 창을 나눈 이유를 따져보면 결국 하나예요. 어느 세션이 나를 기다리는지 알고 싶어서죠.
fmux 는 거기서 출발했어요. 화면은 나누지 않고 지금 보는 세션 하나를 꽉 채워 쓰고, 나머지는 하단 한 줄이 대신 말해주게 하는 겁니다.

What you get쓰면 생기는 것

⏸ waiting on you 나를 기다리는 중

The one that matters. It is named in the status bar, so you know which session is blocked without opening anything.

제일 중요한 상태예요. 상태바에 이름까지 떠서, 아무것도 열지 않고도 어느 세션이 막혀 있는지 알 수 있습니다.

✻ working 작업 중

Actually running right now — judged from agent hooks and CPU, not from guessing at what the screen looks like.

지금 실제로 돌고 있다는 뜻이에요. 화면 모양을 보고 짐작하는 게 아니라 에이전트 훅과 CPU로 판단합니다.

✓ finished while away 자리 비운 사이 끝남

Unread results sit at the top of the list and clear themselves the moment you visit.

안 읽은 결과가 목록 맨 위로 올라오고, 한 번 들르면 알아서 사라집니다.

survives a reboot재부팅해도 살아남아요

fmux --restore brings the whole fleet back — every session in its own directory, each agent resuming its own conversation.

fmux --restore 하나로 함대가 통째로 돌아옵니다. 세션은 원래 디렉토리로, 에이전트는 원래 대화로요.

remote control stays up원격 제어가 안 끊겨요

Claude Code's bridge drops on a 25-minute timeout, on compaction, and when idle, and reconnecting is manual. fmux watches for that and reattaches. Linux only.

폰에서 열어보려면 Claude Code 가 원격 제어 브리지에 붙어 있어야 하는데, 25분 타임아웃·컴팩션·유휴에 끊기고 다시 붙이는 건 수동이에요. fmux 가 지켜보다 알아서 다시 붙여줍니다. 리눅스 전용이에요.

At home on a server서버에 올려두고 쓰기 좋게

One bash file with no runtime can just live on the box your agents actually run on — a Pi, a VPS, the workstation you ssh into. Two things follow from that.

런타임이 필요 없는 bash 파일 하나라, 에이전트가 실제로 도는 기계에 그냥 올려둘 수 있어요. 파이든 VPS든, ssh 로 들어가는 작업용 머신이든요. 여기서 두 가지가 따라옵니다.

It comes back after a reboot. One @reboot cron line rebuilds the fleet: every session in its own directory, every agent resuming its own conversation, not a fresh shell that lost the thread.

재부팅해도 돌아옵니다. @reboot 크론 한 줄이면 함대가 다시 세워져요. 세션은 원래 디렉토리로, 에이전트는 원래 대화로 돌아옵니다. 맥락을 잃어버린 빈 셸이 아니라요.

Conversation identity is the hard part. claude --resume only finds a conversation from the folder it was born in, and that is usually not the session's working directory, so fmux records the two separately and restores them separately.

어려운 건 대화를 다시 찾는 쪽이에요. claude --resume 은 그 대화가 태어난 폴더에서만 대화를 찾는데, 그게 대개 세션의 작업 디렉토리가 아니거든요. 그래서 fmux 는 둘을 따로 기록해두고 따로 복원합니다.

Remote Control stays attached. Claude Code's bridge drops on a 25-minute timeout, on compaction, and when idle, and reconnecting is manual. A second cron line watches for that and reattaches, so a session is reachable from your phone when you look.

원격 제어가 끊긴 채로 있지 않아요. Claude Code 의 브리지는 25분 타임아웃이나 컴팩션, 유휴 상태에서 끊기는데 다시 붙이는 건 수동이에요. 크론 한 줄을 더 넣어두면 그걸 지켜보다 알아서 다시 붙여줍니다. 폰으로 열었을 때 세션이 거기 있는 이유예요.

The installer prints both cron lines and never edits your crontab itself.

크론 두 줄은 설치 스크립트가 화면에 찍어주기만 해요. crontab 을 직접 고치지는 않습니다.

Install설치

curl -fsSL https://raw.githubusercontent.com/gabury1/fleetmux/main/install.sh | bash

Or read it first, which is the reasonable thing to do with any curl | sh — the README shows that path too. The installer checks its dependencies, never edits your crontab, and never takes a key or a file that is already someone else's. Requires tmux ≥ 3.2, fzf ≥ 0.64, bash. Linux and macOS; Windows via WSL2.

아니면 먼저 열어서 읽어보셔도 됩니다. 어떤 curl | sh 든 그게 더 나은 순서고, README 에도 그 경로를 적어뒀어요. 설치 스크립트는 의존성을 먼저 확인하고, crontab 을 고치지 않고, 이미 남의 것인 키나 파일은 가져가지 않습니다. tmux 3.2 이상, fzf 0.64 이상, bash 가 필요해요. 리눅스와 macOS 를 지원하고, 윈도우는 WSL2 로 씁니다.

The agent hooks arrive through a PATH shim that only fires inside tmux. Your global Claude Code config is never touched, and deleting one file removes every trace.

에이전트 훅은 tmux 안에서만 발동하는 PATH shim 으로 주입돼요. 전역 Claude Code 설정은 건드리지 않고, 파일 하나만 지우면 흔적이 전부 사라집니다.
