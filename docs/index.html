fleetmux

Keep the agent screen you already use. fmux adds one status line and one keystroke — nothing else to look at.

쓰던 에이전트 화면 그대로. fmux 가 더하는 건 상태줄 한 줄과 단축키 하나뿐이다.

One bash file. No dashboard, no app, no runtime.

bash 파일 하나. 대시보드도, 앱도, 런타임도 없다.

GitHub Latest release최신 릴리스

The problem문제

Run five agents at once and the expensive one is not the slow session — it is the one that finished asking you a question forty minutes ago and has been idle ever since.

에이전트를 다섯 개쯤 띄워놓고 일하다 보면, 제일 아까운 건 오래 걸리는 세션이 아니다. 40분 전에 뭘 물어봐놓고 그때부터 답을 기다리며 가만히 있는 세션이다.

You cannot see that from outside the session, so you go in and look. Five times. Then you do it again in ten minutes.

근데 그건 들어가 보기 전에는 모른다. 그래서 하나씩 열어본다. 다섯 번. 10분 뒤에 또 다섯 번.

The usual answer is a dashboard — another window, another layout, one more thing to look at instead of the session you were working in. But the screen was never the problem. You liked the screen. You just needed to know when a different one wanted you.

보통은 여기서 대시보드로 간다. 창을 하나 더 띄워서 전체를 한눈에 보는 것. 그런데 화면이 불편해서 이러고 있던 게 아니다. 클로드 화면은 그대로 좋았다. 모자랐던 건 하나뿐이었다. 옆에서 누가 나를 부르는지 모른다는 것.

What you get쓰면 생기는 것

⏸ waiting on you 나를 기다리는 중

The one that matters. It is named in the status bar, so you know which session is blocked without opening anything.

제일 중요한 상태. 상태바에 이름까지 뜨기 때문에, 아무것도 열지 않고도 어느 세션이 막혀 있는지 안다.

✻ working 작업 중

Actually running right now — judged from agent hooks and CPU, not from guessing at what the screen looks like.

지금 실제로 돌고 있다는 뜻. 화면 모양을 보고 추측하는 게 아니라 에이전트 훅과 CPU로 판정한다.

✓ finished while away 자리 비운 사이 끝남

Unread results sit at the top of the list and clear themselves the moment you visit.

안 읽은 결과가 목록 맨 위에 올라오고, 한 번 들르는 순간 알아서 사라진다.

survives a reboot재부팅을 견딘다

fmux --restore brings the whole fleet back — every session in its own directory, each agent resuming its own conversation.

fmux --restore 하나로 함대가 통째로 돌아온다. 세션마다 원래 디렉토리로, 에이전트마다 원래 대화로.

When you come back자리 비운 사이에

The box reboots at 4am. You are not there.

새벽 네 시에 박스가 재부팅된다. 나는 없다.

Add one @reboot cron line and the fleet comes back on its own — every session in its own directory, every agent resuming its own conversation, not a fresh shell that lost the thread. The installer prints that line for you and never edits your crontab itself.

@reboot 크론 한 줄만 넣어두면 함대가 알아서 돌아온다 — 세션마다 원래 디렉토리로, 에이전트마다 원래 대화로. 맥락을 잃어버린 빈 셸이 아니라. 설치 스크립트는 그 줄을 찍어주기만 하고 crontab 을 직접 고치지는 않는다.

That last part is the hard one. claude --resume only finds a conversation from the folder it was born in, and that is usually not the session's working directory. So fmux records the two separately, and restores them separately.

마지막 게 어려운 부분이다. claude --resume 은 그 대화가 태어난 폴더에서만 대화를 찾는데, 그건 대개 세션의 작업 디렉토리가 아니다. 그래서 fmux 는 둘을 따로 기록하고 따로 복원한다.

And by the time you check in from your phone, Claude Code's remote-control bridge has usually dropped — it times out at 25 minutes, on compaction, and when idle, and reconnecting is manual. A second cron line watches for that and reattaches, so the session is there when you look.

그리고 폰으로 들여다볼 때쯤이면 Claude Code 의 원격 제어 브리지는 대체로 끊겨 있다 — 25분 타임아웃, 컴팩션, 유휴에 끊기고, 다시 붙이는 건 수동이다. 두 번째 크론 줄이 그걸 지켜보다가 다시 붙여둔다. 그래서 볼 때 거기 있다.

Install설치

curl -fsSL https://raw.githubusercontent.com/gabury1/fleetmux/main/install.sh | bash

Or read it first, which is the reasonable thing to do with any curl | sh — the README shows that path too. The installer checks its dependencies, never edits your crontab, and never takes a key or a file that is already someone else's. Requires tmux ≥ 3.2, fzf ≥ 0.64, bash. Linux and macOS; Windows via WSL2.

아니면 먼저 열어서 읽어도 된다. 어떤 curl | sh 든 그게 온당한 순서고, README 에도 그 경로가 적혀 있다. 설치 스크립트는 의존성을 먼저 확인하고, crontab 을 고치지 않고, 이미 남의 것인 키나 파일은 가져가지 않는다. 요구사항은 tmux ≥ 3.2, fzf ≥ 0.64, bash. 리눅스·macOS 지원, 윈도우는 WSL2.

The agent hooks arrive through a PATH shim that only fires inside tmux. Your global Claude Code config is never touched, and deleting one file removes every trace.

에이전트 훅은 tmux 안에서만 발동하는 PATH shim 으로 주입된다. 전역 Claude Code 설정은 건드리지 않고, 파일 하나 지우면 흔적이 전부 사라진다.
