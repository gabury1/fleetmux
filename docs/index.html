fleetmux

A tmux cockpit for AI coding agents that live on a server, not on your laptop.

노트북이 아니라 서버에 사는 AI 코딩 에이전트를 위한 tmux 조종석.

One bash file. Survives a reboot. Reachable from your phone.

bash 파일 하나. 재부팅을 견디고, 폰에서 닿는다.

GitHub Latest release최신 릴리스

The problem문제

Run five agents at once and the expensive one is not the slow session — it is the one that finished asking you a question forty minutes ago and has been idle ever since.

에이전트를 다섯 개 굴려 보면, 제일 비싼 세션은 느린 세션이 아니다. 40분 전에 질문을 던져놓고 그때부터 아무것도 안 하고 있는 세션이다.

Which is worse when the fleet is not on the machine in front of you. It is on the box in the corner that stays on, and you visit it — from a laptop, from a phone, after a night's sleep. You cannot see who is stuck from outside the session, so you go in and look. Five times. Then you do it again in ten minutes.

함대가 눈앞의 기계에 없으면 더 나쁘다. 함대는 구석에서 계속 켜져 있는 박스에 살고, 나는 거기로 방문한다 — 노트북에서, 폰에서, 한숨 자고 나서. 누가 막혀 있는지는 세션 밖에서 안 보이니까 들어가서 확인한다. 다섯 번. 그리고 10분 뒤에 또 한다.

What you get쓰면 생기는 것

⏸ waiting on you 나를 기다리는 중

The one that matters. It is named in the status bar, so you know which session is blocked without opening anything.

제일 중요한 상태. 상태바에 이름까지 뜨기 때문에, 아무것도 열지 않고도 어느 세션이 막혀 있는지 안다.

✻ working 작업 중

Actually running right now — judged from agent hooks and CPU, not from guessing at what the screen looks like.

지금 실제로 돌고 있다는 뜻. 화면 모양을 보고 추측하는 게 아니라 에이전트 훅과 CPU로 판정한다.

✓ finished while away 자리 비운 사이 끝남

Unread results sit at the top of the list and clear themselves the moment you visit.

안 읽은 결과가 목록 맨 위에 올라오고, 한 번 들르는 순간 알아서 사라진다.

survives a reboot재부팅을 견딘다

fmux --restore brings the whole fleet back — every session in its own directory, each agent resuming its own conversation.

fmux --restore 하나로 함대가 통째로 돌아온다. 세션마다 원래 디렉토리로, 에이전트마다 원래 대화로.

Why not just read the screen?그냥 화면을 읽으면 안 되나?

Because that was the first version, and it was wrong three separate ways. Spinner wording changes between releases. An idle session still repaints its status line. Attaching to a session reflows it and every heuristic shifts underneath you.

첫 버전이 그거였고, 세 군데에서 각각 틀렸다. 스피너 문구는 릴리스마다 바뀐다. 놀고 있는 세션도 상태줄은 계속 다시 그린다. 세션에 붙는 순간 화면이 재배치되면서 모든 휴리스틱이 발밑에서 어긋난다.

The screen is a rendering, not the content.

화면은 내용이 아니라 렌더링 결과다.

So state comes from the agent itself. Claude Code and Codex hooks report working / idle / waiting as they happen, and fmux draws what they said. The hooks are injected through a PATH shim that only fires inside tmux — your global config is never touched, and deleting one file removes every trace.

그래서 상태는 에이전트 본인한테서 받는다. Claude Code·Codex 훅이 working / idle / waiting 을 그때그때 알려주고, fmux 는 들은 대로 그린다. 훅은 tmux 안에서만 발동하는 PATH shim 으로 주입된다 — 전역 설정은 건드리지 않고, 파일 하나 지우면 흔적이 전부 사라진다.

Install설치

curl -fsSL https://raw.githubusercontent.com/gabury1/fleetmux/main/install.sh | bash

Or read it first, which is the reasonable thing to do with any curl | sh — the README shows that path too. The installer checks its dependencies, never edits your crontab, and never takes a key or a file that is already someone else's. Requires tmux ≥ 3.2, fzf ≥ 0.64, bash. Linux and macOS; Windows via WSL2.

아니면 먼저 열어서 읽어도 된다. 어떤 curl | sh 든 그게 온당한 순서고, README 에도 그 경로가 적혀 있다. 설치 스크립트는 의존성을 먼저 확인하고, crontab 을 고치지 않고, 이미 남의 것인 키나 파일은 가져가지 않는다. 요구사항은 tmux ≥ 3.2, fzf ≥ 0.64, bash. 리눅스·macOS 지원, 윈도우는 WSL2.
