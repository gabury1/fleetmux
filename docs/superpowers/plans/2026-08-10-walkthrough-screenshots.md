# 사용법 스크린샷 다섯 장 — 촬영 계획

랜딩(`docs/index.html`)의 "쓰는 법" 절에는 책갈피 다섯 개가 있고, 각 패널 안에
`.shot-todo` 자리표시자가 비어 있다. 이 문서는 그 다섯 자리를 무엇으로 어떻게
채울지 정한다.

작성 2026-08-10. 은수 지시: *"스크린샷도 너가 좀 채워봐 … 계획 세워가면서 해.
대충하지 말고 … 문서화를 해놔 어떤 스크린샷 넣을지. 서브에이전트로 검증도 하고."*

---

## 0. 지켜야 할 것 (이게 계획의 절반이다)

| # | 제약 | 왜 |
|---|---|---|
| C1 | **팀 내부 정보 0** | 8/6 에 테스트 픽스처에서 실명·도메인 모델·내부 경로를 걷어냈다. 공개 이미지에 그게 다시 들어가면 같은 사고다 |

## 1. 함대 구성 — 다섯 장이 같은 한 함대에서 나온다

장면마다 함대를 새로 세우면 세션 이름이 장마다 달라져서, 다섯 장을 나란히 놓았을 때
같은 화면이라는 게 안 읽힌다. **하나를 세우고 다섯 번 찍는다.**

```
이름        무엇          상태     왜 이 이름인가
─────────────────────────────────────────────────────────────
parser      claude        ⏸       "어디로 갈지 알려주는 이름" 의 예. 03 장에서 이 이름이 된다
api         claude        ✻       작업 중 하나는 있어야 배지가 둘 이상으로 보인다
docs        claude        ✓       자리 비운 사이 끝남
logs        yazi          (없음)   도구 세션 — 목록에 색이 다른 줄이 하나 있어야 분류가 보인다
```

이름 넷 다 중립어다(C1). 도메인·사람·회사 흔적 없음.

### ⚠️ 촬영 순서가 강제된다 (검수에서 잡힘)

03 장은 `bash-3` 을 `parser` 로 바꾸는 장면이다. 그런데 §1 표는 `parser` 가 이미
있다고 적는다. **tmux 는 같은 이름의 세션을 둘 허용하지 않으므로**, 함대를 `parser`
로 세워두고 03 을 찍으면 rename 이 이름 충돌로 실패한다.

그래서 순서가 계획의 일부다. 스크립트가 이 순서를 강제해야 C4(재현 가능)가 성립한다.

```
① 함대를 세운다 — 단, parser 자리는 bash-3 이라는 이름으로
② 03 을 찍는다 (bash-3 → parser 로 바꾸는 순간)
③ rename 이 실제로 끝난다 → 이제 함대에 parser 가 있다
④ 01 · 02 · 04 · 05 를 찍는다
```

부수 효과가 좋다 — 다섯 장이 **찍힌 순서 그대로 시간순**이 되고, 03 이 `parser` 의
출처를 설명한다. 03 을 먼저 찍는 게 제약이 아니라 서사가 된다.

## 2. 실제 클로드를 띄우는가 — 반반으로 간다

은수: *"실제 클로드 세션 띄워도 좋아."* 그래도 전부 실제로 띄우는 건 틀린 선택이다.

| 무엇 | 실제인가 | 근거 |
|---|---|---|
| **fmux 가 그리는 것 전부**<br>(팝업·목록·상태줄 배지·프리뷰·프롬프트 창) | **실제** | 이게 찍는 대상이다. 여기를 그리면 스크린샷이 거짓말이 된다 |
| 세션 안 클로드 화면 (배경에 깔리는 것) | **실제 1개 + 나머지는 화면 텍스트** | 아래 |

**왜 하나만 실제인가.** 04 장은 "세션에 들어간 화면" 위에 팝업이 겹친 그림이라, 그
배경이 진짜 클로드여야 한다 — 거기만 실제로 띄운다. 나머지 셋은 목록 뒤에 깔릴 뿐이고,
넷을 동시에 띄우면 (a) 토큰을 쓰고 (b) 매 촬영마다 화면이 달라져 C4 가 깨진다.

### ⚠️ 실제 클로드 한 개를 띄울 때의 격리 (검수에서 잡힌 갭)

`demo/fleet.sh` 의 기존 방어(PS1 초기화·status-left 비우기·automatic-rename off)는
**"cat 으로 그린 가짜 화면"을 전제로 설계된 것**이다. 진짜로 도는 클로드가 스스로
그리는 UI — footer, 폴더 신뢰 대화상자, `/mcp` 목록, 스킬 목록, resume 배너,
커스텀 statusline — 은 그 방어선 어디에도 안 걸린다.

실측한 유출 경로(2026-08-10):

```
$HOME 격리 안 하면  →  ~/.claude.json 의 mcpServers: tm-linear · tm-slack · tm-notion
                       ~/.claude/skills/ 의 ac-control 등 팀·개인 스킬 이름
                       resume 목록에 실제 과거 대화 제목
cwd 격리 안 하면    →  /home/euns/... 절대경로 (사용자명이 샌다)
                       git 브랜치명 (워크플로 관례가 샌다)
```

8/6 에 테스트 픽스처에서 걷어낸 것과 **정확히 같은 종류**다. 그래서 04 장의 클로드는
아래를 전부 만족하는 상태에서만 띄운다:

- [ ] `HOME` 을 촬영용 임시 디렉토리로 바꾼다 (`demo/fleet.sh` 가 이미 하는 것)
- [ ] 그 HOME 에 **빈 `.claude.json`** 을 둔다 — MCP 0개, 스킬 0개
- [ ] 세션 cwd 를 촬영용 디렉토리로 준다 (`tmux new-session -c`). 실레포 안에서 띄우지 않는다
- [ ] git 저장소가 아닌 곳에서 띄운다 — 브랜치 표시 자체를 없앤다
- [ ] 첫 실행 신뢰 대화상자를 미리 통과시켜 둔다 (촬영 프레임에 안 뜨게)
- [ ] 찍은 뒤 **육안으로 한 줄씩** 확인한다. 이건 자동 검수로 못 잡는다

프롬프트는 이 레포 자체에 대한 무해한 것으로 한다(예: "이 bash 파일에서 함수 목록을
뽑아줘"). 팀 코드·도메인 얘기는 한 글자도 넣지 않는다.

**⚠️ 정직성 경계.** `demo/README.md` 가 기존 GIF 에 대해 이미 *"painted, not run"* 을
밝히고 있다. 같은 문장을 이 스크린샷에도 적용해 `demo/screenshots/README.md` 에
어느 부분이 실제이고 어느 부분이 화면 텍스트인지 적는다. 페이지 본문에는 안 적는다 —
찍는 대상(fmux UI)은 전부 실제라 본문에서 해명할 것이 없다.

**훅 상태는 손으로 쓴다.** ⏸/✻/✓ 를 실제로 만들려면 승인 프롬프트를 띄우고 40분을
기다려야 한다. `demo/fleet.sh` 가 이미 하는 방식대로 `hook-<id>` 를 직접 쓴다.
⚠️ 8/6 에 겪은 함정: 훅 파일에는 **tmux 서버 pid** 와 **현재 timestamp** 가 둘 다
맞아야 `fmux_hook_valid` 를 통과한다. 그리고 어제(8/9) 안티스턱 가드가 들어갔으므로
**`ts` 가 신선해야 한다** — `working` 은 180초(`FMUX_STUCK_AFTER`), `waiting` 은
60초(`FMUX_STALE_WAIT`) 안쪽이어야 배지가 뜬다. 촬영 직전에 다시 쓴다.

## 3. 다섯 장

각 장의 **정답 조건**을 적는다. 찍고 나서 이걸로 검수한다.

### 01 — 들어가기

> 패널 문구: 터미널에서 `fmux` 를 치면 세션 목록이 나오고, 고른 세션에 붙습니다.
> 일단 안에 들어오면 `Shift + ↑` 하나면 같은 팝업이 열립니다.

**두 가지를 말하는 패널이라 한 장에 둘 다 있어야 한다.**

- 화면 위쪽: 셸 프롬프트에 `$ fmux` 를 친 흔적이 남아 있다
- 화면 가운데: 그 결과로 열린 목록
- 목록에 `⏸ parser` 가 보인다 (다음 장들과 같은 함대라는 증거)

정답 조건:
- [ ] `$ fmux` 타이핑이 화면에 남아 있다
- [ ] 세션 넷이 다 보인다
- [ ] `logs` 가 다른 색(도구 세션)이다
- [ ] 프리뷰 칸에 마지막 프롬프트가 있다

### 02 — 새 세션 만들기

> `Ctrl + N` … 이름과 실행할 명령을 물어봐요.

정답 조건:
- [ ] 이름을 묻는 입력 상태가 보인다 (커서가 입력칸에)
- [ ] 뒤에 기존 목록이 깔려 있다 — "팝업 안에서 하는 일" 이 읽혀야 한다
- [ ] 입력 중인 이름은 중립어(`worker`)

### 03 — 이름 바꾸기

> `Ctrl + E` … `parser` 는 어디로 갈지 알려주지만 `bash-3` 은 안 알려주거든요.

**패널 문구가 `parser` 와 `bash-3` 을 예로 든다. 스크린샷이 그 문장과 같아야 한다.**
→ 촬영용 함대에 `bash-3` 이라는 이름의 세션을 하나 더 만들고, 그걸 `parser` 로
바꾸는 순간을 찍는다. 그러면 §1 의 `parser` 가 어디서 왔는지도 설명된다.

정답 조건:
- [ ] 바꾸기 전 이름 `bash-3` 이 목록에 보인다
- [ ] 입력칸에 새 이름을 치는 중이다
- [ ] 문서 문구와 이름 둘 다 일치

### 04 — 오가기

> `→` 로 들어가요 … `Shift + ↑` 는 세션 안에서도 똑같이 먹어서

**여기가 유일하게 실제 클로드가 배경에 필요한 장.** 세션에 들어간 화면 위로 팝업이
겹쳐 있어야 "안에서도 부를 수 있다" 가 그림으로 읽힌다.

⚠️ **`●` 를 정답 조건으로 걸면 안 된다** (검수에서 잡힘). 팝업은 자기를 연 세션을
목록에서 **빼고** 그린다(`src/80-view.sh:201`, `[ "$name" = "${FMUX_CUR:-}" ] && continue`).
`●` 는 `#{session_attached}` 라 *다른* 세션에 별도 클라이언트가 붙었을 때만 뜬다.
"지금 들어와 있는 세션이 목록에 ● 로 보인다"는 구조적으로 불가능한 장면이다.

그래서 이 장이 증명해야 하는 것은 다르게 잡는다 — **배경에 보이는 세션 이름이 목록에는
없다**는 것 자체가 "나는 지금 그 안에 있다"의 증거다.

정답 조건:
- [ ] 배경에 실제 클로드 세션 화면, 그 세션 이름이 tmux 상태줄에 보인다
- [ ] 그 위에 팝업이 떠 있다
- [ ] 팝업 목록에 **배경 세션 이름이 없다** (현재 세션은 빠지므로)
- [ ] 배경 클로드 화면에 팀 정보 0 — §2 의 격리 체크리스트를 전부 통과한 상태

### 05 — 나중에 다시 들어가기

> 재부팅해도 함대가 그대로 … 다시 세우는 게 아니라 찾아 들어가는 겁니다.

**"복원됐다" 를 한 장으로 보이는 게 제일 어렵다.** 그냥 목록을 찍으면 01 과 구별이
안 된다. → **before/after 를 한 장에** 넣는다:

```
윗칸:  $ tmux -S … kill-server      ← 함대가 죽었다
       $ fmux --restore
아랫칸: 되살아난 목록 (같은 이름 넷)
```

한 터미널에서 위아래로 이어지는 한 장이라, 텍스트 없이도 인과가 읽힌다.

정답 조건:
- [ ] `kill-server` 가 화면에 있다 (죽였다는 증거)
- [ ] `--restore` 출력이 세션 이름을 나열한다
- [ ] 복원 뒤 목록의 이름이 01 과 **같다**

## 4. 어떻게 찍는가

### 도구

`vhs`(있음, `~/.local/bin/vhs`) 를 쓴다. `.tape` 파일이 곧 재현 스크립트이므로 C4 를
공짜로 만족한다. `Output foo.png` 로 마지막 프레임을 PNG 로 뽑을 수 있다.

⚠️ 8/6 실측: **vhs 의 modifier 는 문자를 받는다 — `Shift+Up` 을 못 보낸다.**
그래서 팝업을 여는 것은 키를 흉내내지 말고 `tmux -S <sock> run-shell` 이나 그냥
`display-popup` 을 직접 호출한다. *찍는 대상은 팝업의 생김새지 키 입력이 아니다.*

### 소환키를 함대 config 에 박는다

`key_summon_fast` 의 **코드 기본값은 빈 문자열**이다(`src/05-config.sh:45`) — fmux 는
아무 키도 빼앗지 않은 채로 설치된다. `S-Up` 은 설치 스크립트가 *제안*하는 값일 뿐이다.

페이지 01 장이 `Shift + ↑` 를 말하므로, 촬영 함대는 그 키가 실제로 걸린 상태여야
그림과 글이 맞는다. `demo/fleet.sh:13` 이 이미 하는 방식대로 config 에 직접 쓴다.

```
printf 'key_summon_fast=S-Up\naccent=73\n' > "$HOME/.config/fleetmux/config"
```

### 색

`.tape` 에 페이지 팔레트를 그대로 준다.

```
Set Theme { "background": "#0f1319", "foreground": "#c8d3d5",
            "cyan": "#4ec9b0", "yellow": "#d7af5f", "green": "#7fae6e", ... }
Set FontFamily "DejaVu Sans Mono"     # fc-list 로 확인된 것만 쓴다
Set FontSize 15
Set Padding 18
```

### 크기

페이지 본문 폭 880px. 패널 안쪽은 그보다 좁다(≈ 560px). **2배로 찍는다** — 폭 1200px
정도의 PNG. 레티나에서 뭉개지지 않고, `width:100%` 로 축소돼 들어간다.

### 파일

```
docs/shots/01-get-in.png
docs/shots/02-new.png
docs/shots/03-rename.png
docs/shots/04-switch.png
docs/shots/05-later.png
docs/shots/README.md          ← 무엇이 실제이고 무엇이 화면 텍스트인지
demo/shots.sh                 ← 함대를 세우는 스크립트 (fleet.sh 재사용/확장)
demo/shots/*.tape             ← 장면별 촬영 스크립트
```

`docs/` 아래에 두는 이유: GitHub Pages 소스가 `main` 의 `/docs` 라, 그 밖에 두면
페이지에서 404 다(8/7 에 `site/` → `docs/` 로 옮긴 것과 같은 이유).

용량 상한 **장당 400KB**. 넘으면 색수를 줄인다. 다섯 장 합쳐 2MB 를 넘기면 모바일에서
첫 화면이 느려진다.

### 마크업 교체

`.shot-todo` div 를 `<img class="shot" src="shots/NN-….png" alt="…">` 로 바꾼다.
`alt` 는 영/한 각각 쓴다 — `data-lang` 짝 규칙(EK 교대)을 깨지 않도록 주의.
`loading="lazy"` 를 붙인다. 다섯 장 중 넷은 탭을 눌러야 보이므로 첫 로드에서 받을
이유가 없다.

| 축 | 무엇을 보나 |
|---|---|
| **정보 유출** | 다섯 장 전부에서 사람 이름·회사·도메인·내부 경로·토큰·실제 홈 디렉토리 흔적. C1 위반 0 이어야 통과 |
| **문서 정합** | 패널 문구가 말하는 키/이름/동작이 그림과 일치하나. 특히 03 의 `bash-3`→`parser`, 04 의 `●`, 05 의 같은 이름 |
| **없는 기능** | 다섯 장 어디에도 이 빌드에 없는 것이 보이면 실패 — `Alt+N` 다중 생성(구현 0), 그리고 rc 배지 `⊘` 는 리눅스에서만 뜨므로 macOS 독자에게 되는 것처럼 보이면 안 된다 |

셋 다 통과해야 커밋한다. 하나라도 걸리면 그 장만 다시 찍는다.

## 6. 안 하는 것

- **GIF 로 만들지 않는다.** 다섯 장은 "이 키를 누르면 이 화면" 이라 정지 화면으로
  충분하고, 탭 안에서 다섯 개가 동시에 움직이면 산만하다
- **애니메이션 전환 없음.** 탭 전환은 이미 CSS 로 즉시 바뀐다
- **터미널 창틀(맥 신호등 등) 안 그린다.** 페이지가 이미 어두운 패널 안이라 액자가
  이중이 된다

## 판단 로그

**다섯 장을 한 함대에서 찍기로 한 것이 이 계획의 중심 결정이다.** 장마다 따로 세우면
각 장은 더 쉽게 찍히지만, 다섯 개를 차례로 클릭하는 사람에게는 매번 다른 화면이 된다.
같은 이름이 다섯 번 나오면 그것만으로 "하나의 흐름" 이 된다.

**03 장에 `bash-3` 을 일부러 만든 이유** — 패널 문구가 그 두 이름을 예로 드는데
스크린샷에 없으면, 글과 그림이 각자 다른 얘기를 한다. 그리고 그 장면이 §1 의 `parser`
출처를 설명해서 다섯 장이 시간순으로 이어진다.

**05 장을 before/after 한 장으로 만든 이유** — 복원은 *변화*라서 결과만 찍으면 아무것도
안 보인다. 죽인 명령과 되살아난 목록이 한 화면에 있어야 인과가 그림으로 남는다.
